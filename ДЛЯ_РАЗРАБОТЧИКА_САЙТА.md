# FISHING UNBOUND — подключение сайта к API бота

Ответ на «Договорённость по интеграции FISHING UNBOUND». Все пять пунктов готовы, основной API работает по HTTPS.

## 1. Адрес и переменные Netlify

```
FISHING_UPSTREAM_API_URL = https://45-134-217-51.sslip.io:47821/api
FISHING_UPSTREAM_API_KEY = <передаём отдельно, в личных сообщениях>
```

- Сертификат Let's Encrypt настоящий (не самоподписанный), Caddy продлевает его сам. `45-134-217-51.sslip.io` указывает на IP сервера. Если позже появится свой домен, поменяется только `FISHING_UPSTREAM_API_URL`.
- `FISHING_PUBLIC_READ_API_KEY` **не нужен**: `GET /api/news` публичный.
- Старый адрес `http://45.134.217.51:47821` больше не работает: на этом порту теперь только HTTPS.

Проверка:

```
curl https://45-134-217-51.sslip.io:47821/api/health   → {"ok": true, "service": "KrakenBot news API"}
curl https://45-134-217-51.sslip.io:47821/api/news     → {"news": [...], "total": N}
```

## 2. Как это закрывает ваши пункты

| Пункт | Реализация |
|---|---|
| 1. HTTPS | Caddy, Let's Encrypt, порт 47821 |
| 2. `POST /api/auth/login` → `{access_token, expires_in}` | ✅ `expires_in: 3600`, плюс `token_type: "Bearer"` |
| 2. `GET /api/auth/me` с Bearer | ✅ `{"authenticated": true, "user": {"username", "name", "discord_id", "avatar_url", "roles": ["admin"]}, "expires_at"}` |
| 2. `POST /api/news` с проверкой роли | ✅ Роль проверяется на **каждом** запросе (см. раздел 3) |
| 3. `GET /api/news` — только опубликованное | ✅ `{"news": [{id, date, title, body, ...}], "total"}`, новые сверху |
| 4. Межсервисный ключ | ✅ `X-API-Key` = `FISHING_UPSTREAM_API_KEY`. Он обязателен для login/me/logout/POST, но **прав не даёт**: без токена администратора запись запрещена |
| 5. Новости из Discord в той же базе | ✅ Новость, опубликованная кнопкой в Discord, сразу есть в `GET /api/news` (`"source": "discord"`) |
| Защита от дублей | ✅ Повтор с тем же `Idempotency-Key` или `external_id` возвращает уже созданную новость (`200`). Без ключа повтором считается та же пара `title` + `body` в течение 10 минут |
| Отзыв токена | ✅ Есть `POST /api/auth/logout` на сервере (Bearer + `X-API-Key`). Вызывайте его из своего `/api/auth/logout`, чтобы токен отзывался сразу |

## 3. Учётные записи администраторов

Пользователей заводит не сайт, а Discord-бот:

1. Участник с ролью поддержки нажимает в закрытом канале бота кнопку **🔑 Доступ к сайту**.
2. Бот показывает ему личный логин (имя пользователя в Discord) и случайный пароль.
3. С этими данными он входит на `/admin.html`.

Права проверяются **на каждом защищённом запросе**: если у человека забрали роль в Discord, его токен сразу перестаёт работать (`401`). Повторное нажатие кнопки выдаёт новый пароль и закрывает все старые входы. После 5 неверных паролей вход по этому логину блокируется на 15 минут (`429`).

## 4. Что поправить в `fishing-api.mjs`

1. **Длина текста:** у вас `body` до 6000 символов, у нас до **4000** (лимит сообщения Discord). Иначе длинная новость вернётся с `422 validation_error`. Заголовок: у вас 160, у нас 250, тут всё совместимо.
2. **Отзыв токена при выходе (желательно):** в `/api/auth/logout`, перед очисткой cookie, вызовите `POST {upstream}/api/auth/logout` с `Authorization: Bearer <token из cookie>` и `X-API-Key`.
3. **Защита от дублей (желательно):** передавайте в `POST /api/news` заголовок `Idempotency-Key: <uuid>`, один и тот же при повторах одной публикации.
4. **`status`:** принимаем только `"published"`, черновики сервер не хранит.

Всё остальное (`date` в формате `YYYY-MM-DD`, `title`, `body`, формат `{news: [...]}`, Bearer + `X-API-Key`, ответ login) совпадает с вашим кодом без изменений. Ленту `GET /api/news` мы прогнали через разбор из `public-feed.js` (строки 25–32), ошибок нет.

## 5. Ошибки

Формат: `{"error": "<код>", "message": "<описание по-русски>"}`

| HTTP | `error` | Когда |
|---|---|---|
| 400 | `bad_json`, `bad_query`, `guild_required` | неверный запрос |
| 401 | `unauthorized`, `invalid_credentials` | нет `X-API-Key`, неверный логин или пароль, токен истёк, у пользователя нет роли |
| 403 | `discord_forbidden` | у бота нет прав в канале новостей |
| 404 | `not_found` | новость не найдена |
| 409 | `news_channel_not_set` | в боте не выбран канал новостей |
| 422 | `validation_error` | поля не прошли проверку (`message` объясняет, какие) |
| 429 | `too_many_attempts` | много неудачных входов |

## 6. Дополнительно (если пригодится)

- `GET /api/news/{id}`, `PATCH /api/news/{id}` (`title`, `body`, `date`), `DELETE /api/news/{id}` — меняют и удаляют новость вместе с сообщением в Discord.
- `POST /api/news` принимает также `images` (до 10 ссылок `https://`, в Discord показываются сеткой) и `mention` (`none` / `everyone` / `here`).
- Можно настроить вебхук: бот сам отправит на сайт `news.created` / `news.deleted` с подписью HMAC. Но сайт и так читает ленту из `GET /api/news`, поэтому вебхук не обязателен.

Полное описание: [API.md](https://github.com/luviel19/KrakenBot/blob/main/API.md).

## 7. Проверка после деплоя

1. `https://fishing-unbound.netlify.app/api/config` → `"admin_enabled": true`
2. `https://fishing-unbound.netlify.app/api/news` → новости с сервера
3. `/admin.html` → вход по данным из кнопки **🔑 Доступ к сайту** → публикация → новость появилась на сайте **и** в Discord
4. Публикация кнопкой **📰 Опубликовать новость** в Discord → новость появилась на сайте
